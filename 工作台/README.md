# 个人工作台

双击 `index.html`，即可在浏览器打开工作台。顶部导航分为「总览、今日待办、待跟进、待触达、流转倒计时、已处理、全部事项」七个视图；点击即可切换，不会清空当前浏览器保存的事项。总览显示可点击的关键数字和事项处理进度圆环；原来的四个通用区块收在「全部事项」。后续可按 `agent.md` 逐步增加工作流。

## 日常使用

1. 点击「添加事项」，手动记录邮件待回复、KOL 政策待审批、已确认样机在手等事项。可选择 KOL 清单归类，并填写下一步、对方需要什么和判断依据。
2. 点击「导入台账 CSV」，可同时选择 `02-kol-database/KOL主表.csv`、`03-outreach/跟进记录.csv`、`02-kol-database/候选名单-待核实.csv`。重新导入会更新对应来源的事项，已完成状态和你编辑过的内容会保留。
3. 定期点击「导出备份」保存 JSON；换浏览器或清理浏览器数据后，点击「恢复备份」。恢复会替换当前浏览器里的事项。
4. 要给某人补倒计时，进入「流转倒计时」，点击顶部的「待补／核对日期」数字筛出名单，再点该人卡片中的「补日期并计算天数」。选择 KRM 阶段、日期依据和日期后，短弹窗会预览剩余天数；点击底部「保存并查看倒计时」即可返回该人员卡片。完整「编辑事项」弹窗的保存按钮固定在底部。

「已处理」只表示你在工作台勾选了事项完成，不自动表示已经给 KOL 发消息，也不表示 KRM 已更新跟进记录。总览圆环只计算工作台事项的勾选比例。

用户通过对话提供 Excel 跟进表或 KRM 粘贴文本后，助理可在本机运行 `prepare_private_data.py`，生成同目录的 `local-data.js`。页面打开时自动载入这份只含必要摘要的本地文件；再次生成时按版本更新，保留已完成和人工编辑的内容。公开 GitHub 上没有这份本地数据，因此在 GitHub 打开的页面不会自动显示真实 KOL 名单。

2026-09-24 的 KRM 粘贴文本共识别 100 条：22 条欧洲且明确“尚未触达”的线索进入本机清单；77 条非欧洲或地区不明、1 条“首次触达”但没有回复信息的记录没有据此归入待触达或未回复清单。原始粘贴文本保持只读，工作台不保存邮箱、电话、地址和沟通原文。

## KRM 流转倒计时

- 未建联：KRM 中最后一次跟进记录日，缺少时用认领日，估算连续 14 天无记录的公海临界日。
- 谈判中：KRM 中最后一次跟进记录日，缺少时用进入谈判日，估算 14 天的公海临界日。
- 已签约：KRM 中最后一次跟进记录日，缺少时用签约日，估算 28 天进入待分配池的临界日。
- 剩余 3 天以内显示醒目提醒，并进入今日清单。已经处于公海或待分配池的事项不会排入可联系队列。实际阶段、归属和退回时间以 KRM 为准。
- 这次粘贴文本虽有“上一次沟通时间”，但 99 条同时标注“尚未触达”，多数该日期与创建日期相同，不能证明有有效跟进记录，也不等于认领日。这批记录先显示“待补日期”；补录认领日或有证据的最近跟进日后才显示剩余天数。
- 倒计时页的三个数字都是筛选按钮，完整人员名单直接显示在页内。没有可核实的日期时，不能生成某个人具体还剩几天；补录后立即计算并显示。

## 每日 KOL 清单的判断

- **尚未触达**：只有正式主表明确为「待外联」才列入；待核实候选不算。
- **已触达未回复**：表格同时记录首次或二次触达、阶段「未建联」、回复「未回复」。没有发送日期，不判定超期。
- **已回复待核对跟进**：表格有真实回复，但二次沟通栏未记录。先核对邮件线程，不能仅凭空白栏断言完全没有跟进。
- **合作推进与对方需求**：展示原表阶段及回复摘要；若签约状态和阶段矛盾，标明「待核实」。
- **样机在手、脚本待修改**：必须有明确的样机签收与脚本修改记录；目前未记录时显示空状态。
- **今天建议先处理谁**：包括实际到期事项与需要优先核对回复的建议。建议不是约定的截止日。

## 台账如何进入四个区块

- KOL 主表中状态为「待外联」的正式 KOL 进入待触达事项；C 级先放未来事项。
- 跟进记录中的有效跟进进入「跟进中」；到期或超期的跟进显示在「今日待办事项」。`已发货`仅表示需要确认样机是否签收，不代表 KOL 已经拿到样机。
- 已完成公司双重查重、状态为「待核实」的候选人进入「未来工作事项」。未现场核实前，不排入待触达队列。
- 示例行、拒绝联系和已放弃记录不进入待办。缺少日期或状态时不猜测。

## 数据边界

页面不联网。手动事项和导入结果保存在当前浏览器；`local-data.js` 只保存在本机工作台目录，已被 `.gitignore` 排除。GitHub 仓库只保存网页代码、处理脚本和通用说明，不保存你的任务、KOL 台账或备份。邮件、KRM 和公司政策审批目前没有自动接口，需要通过本机文件导入或手动登记。私人地址、联系方式和邮件原文不会进入本地摘要。
