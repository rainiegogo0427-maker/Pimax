| 字段 | 填什么 | 取值约定 |
|---|---|---|
| 录入日期 | 第一次录入的日期 | `YYYY-MM-DD` |
| 平台 | 主要平台 | TikTok / YouTube / Instagram / X / Twitch / Discord / Telegram |
| 账号名 | 带 @ 的用户名 | `@xxx` |
| 主页链接 | 完整 URL | |
| 国家/地区 ⭐ | 用国家代码。**主打欧洲，这一列必填** | DE / AT / UK / IE / NL / BE / FR / PL / IT / ES |
| 语言 ⭐ | 内容主要语言。**必填，决定用哪种语言私信** | 德语 / 英语 / 法语 / 荷兰语 / 波兰语 / 意语 / 西语 |

| 平均播放量 | 近 10 条内容的平均值 | 纯数字 |

## ⭐ 欧洲市场：国家和语言是必填项

**为什么这两列不能留空**：

1. **国家决定这个人能不能合作**——货发不到他的国家，谈成了也没用。开工前必须拿到公司的发货国家清单（见 `00-setup/06-欧洲市场作战要点.md` 第九节）。
2. **语言决定私信用什么写**——用英语找德国达人，回复率会明显低于用德语。
3. **国家决定广告标注用哪个词**——德国要 `Werbung`、法国要 `Publicité`，只写 `#ad` 不合规。

`/scan` 和 `/find` 命令会自动判断并填这两列；判断不出来会标「国家待确认」提醒你去核。

## ⚠️ GDPR 红线（存欧盟居民数据受法律管）

| ✅ 可以存 | ❌ 绝不能存 |
|---|---|
| 公开主页链接、用户名 | 私人手机号 |
| 主页 bio 里**公开**的商务邮箱 | 家庭住址（寄样地址走公司物流系统，不进仓库） |
| 公开的粉丝数、播放量 | 生日、私人社交账号 |
| 他自己报的价格 | 用第三方工具"挖"出来的未公开邮箱 |

另外两条习惯：

- **达人说「别再联系我」→ 状态立刻改「已拒绝-勿再联系」。** `/daily` 不会再把他排进跟进队列。这是 GDPR 下必须能做到的事。
- **超过 24 个月没有任何业务往来的联系人，清理或匿名化**（删掉邮箱，只留账号名和结论）。每季度做一次。

> 具体的合法依据和保留期限，让公司法务给一个明确口径。上面是降低风险的实操习惯。

## 几条使用约定

1. **不确定的一律留空**，不要填「约 10 万」这种模糊值。空值比错值好。
2. **数字列不要带单位或千分位**，写 `120000` 不写 `12万` 也不写 `120,000`，否则没法计算。
3. **每季度核一次数据**：粉丝数和播放量会变，`数据更新日期`超过 3 个月的行要重新看一遍。
4. **不要删行**。谈失败的改状态为「已放弃」并在备注写原因——半年后可能又能谈。
5. 用 Numbers 或 VS Code 编辑。要用 Excel 的话，另存时必须选 **CSV UTF-8**，否则中文会乱码。

## 两张表的分工（重要）

| 文件 | 装什么 | 谁写 |
|---|---|---|
| `候选名单-待核实.csv` | **联网搜来、已经过公司公海查重、但还没现场核实的**。多五列：「我为什么该关注他」「信息来源链接」「公海查重结果」「公海查重时间」「公海命中依据」 | `/find` 流程自动写 |
| `KOL主表.csv` | **已经到主页现场核实过数据的**。这才是正式名单 | `/scan`、`/intake` 写 |

**为什么要分开**：联网搜到的粉丝数常常是旧数据，甚至有账号已经改名或停更。
直接进主表会污染后面所有的评级和 ROI 分析。所以流程是：

```
/find 搜出候选  →  标准化主页链接  →  KRM 名称+链接查重
                                           ↓
                              未发现重复才进候选名单-待核实.csv
      ↓
/scan 浏览器逐个核实  →  KOL主表.csv（状态：待外联）
      ↓
/dm 发首触  →  跟进记录.csv
```

候选名单里核实完的行可以直接删掉，或把「状态」改成「已转入主表」。

### 公海查重字段

| 字段 | 填什么 | 取值约定 |
|---|---|---|
| 公海查重结果 | KRM 名称和标准化主页链接的综合结果 | 未发现重复 / 疑似重复 / 明确重复 / 未查重 |
| 公海查重时间 | 本次查询日期 | `YYYY-MM-DD` |
| 公海命中依据 | 命中了什么，不复制不必要的个人信息 | 例：`KRM名称疑似命中`、`公海标准链接命中`；未命中留空 |

查重时不要只复制浏览器地址栏里的原始 URL。先使用 `tools/normalize_kol_identity.py` 去掉视频页后缀、查询参数等非身份信息。名称命中只能标为「疑似重复」，需要结合平台和主页链接确认；不要因同名直接排除不同达人。
